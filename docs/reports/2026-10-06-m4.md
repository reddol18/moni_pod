# M4 report — 2026-10-06 (lock hooks, two-key gate)

## Built
- `lock.py` — PreToolUse lock (ADR-0002):
  - RunPod MCP (`mcp__*runpod*__…`): `create-pod`, `delete-pod`, `update-pod`, `*-cluster` → deny;
    `pod-action` start/restart/terminate → deny; **stop allowed**; reads pass.
  - Shell (Bash and PowerShell): `runpodctl` create/start/restart/reset/update/delete/remove/rm (new and legacy forms)
    → deny; raw REST pod mutations (POST/DELETE/PATCH to `…/pods`, except a stop action) and GraphQL pod mutations → deny;
    writes to `~/.moni_pod` → deny.
  - Our CLI spending calls (`moni-pod start` incl. `--resume`, `extend`, `stop --action terminate`): no valid
    user-minted token for this session → deny naming the command to type; with one → **ask** with a reason the hook
    computes itself (hardware, max time, max cost, budget; for delete: retrieval answer). `--session` must equal the
    hook's session id; one spending call per command. The hook never consumes tokens (the CLI does).
  - Write/Edit tools on `~/.moni_pod/**` → deny.
- `hooks/hooks.json` — UserPromptExpansion (mint) + PreToolUse on RunPod MCP tools, `Bash|PowerShell`, file-write tools.
- `cli hook pre-tool-use`, `explain_spend()`; token loader fails closed on malformed files.
