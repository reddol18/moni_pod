# moni_pod — 구성안

- 상태: **착수** (2026-10-06, 지휘부 작성). 작업 지시: `docs/tasks/0001-m0-to-m5.md`(M0~M5). M5 후 실제 GPU 작업으로 실용 확인 → M6 여부 결정.
- 한 줄 요약: **AI 에이전트가 쓰는 클라우드 GPU(RunPod)의 "켜져 있는 동안 쌓이는 비용"을, 사용자가 명시적으로 시작·종료하게 만들고 그 밖의 경로는 잠그는 Claude Code 플러그인.**

## 1. 왜 만드나 — 선행 도구와의 차이

2026-10-06 선행조사(검색 ~8회, README 확인 4건. 완전하지 않으니 착수 전 재확인).

| 이미 있는 것 | 하는 일 | 빈 곳 |
|---|---|---|
| RunPod 공식 Claude Code 플러그인(`runpod/runpod-plugins-official`) | 스킬 8개 + 호스팅 MCP(`mcp.getrunpod.io`). Pod 생성·정지·삭제, 가격·지출 조회, `runpodctl`로 SSH·파일 전송 | 에이전트가 대화만으로 GPU를 켤 수 있게 됐지만 **지출을 막는 장치는 없음** |
| 공식 `Runpod-Idle-Pod-Monitor`(v2.3, 2025-11) | CPU·GPU·메모리 사용률이 임계 아래로 지속되면 Pod 정지 | 사용률만 봄. 예산·세션·"누가 만들었나" 개념 없음 |
| 범용 에이전트 예산 가드(Cycles Budget Guard, agentwares/agentguard, policylayer Intercept) | 도구 **호출 1회**의 비용(인자·결과의 cost_usd·LLM 토큰)으로 차단 | Pod 생성 호출은 그 순간 $0. 돈은 **켜져 있는 시간**만큼 쌓인다 → 호출 단위 가드로는 원리상 못 막음 |
| 세션 종료 정리(process-cleanup, agent-atexit) | 로컬 프로세스 정리 | 클라우드 자원은 대상 아님 |

→ **moni_pod가 채우는 곳: 에이전트가 만든 클라우드 자원의 수명 장부(시작 합의 → 실시간 누적 → 종료·정산).** 유휴 감지는 만들지 않는다(공식 Idle Monitor를 쓴다). 바퀴를 새로 만들지 않고 공식 도구 위에 얹는다.

## 2. 설계 원칙 (사용자 결정, 2026-10-06)

1. **시작과 종료는 사용자가 명시적으로 입력한다.** 예산이 걸린 판단(생성, 시간, 정지/삭제)은 전부 명시적 명령 안에서만, 사용자 확인을 거쳐 일어난다.
2. **훅은 판단하지 않고 잠그기만 한다.** 명령을 거치지 않은 직접 생성·삭제 호출(공식 MCP, `runpodctl`, REST)을 거부한다. 자동 정지·삭제를 하는 훅은 만들지 않는다.
3. **최후 방어선은 Pod 안에 둔다.** 시작할 때 사용자가 합의한 최대 사용 시간(TTL)이 지나면 Pod가 스스로 정지한다. 이 PC가 꺼지거나 Claude Code가 비정상 종료돼도 동작해야 한다.
4. **결과 파일을 회수하지 않은 Pod는 자동 삭제하지 않는다.** 삭제는 `/gpu-stop`에서 사용자가 고를 때만.
5. **정지 ≠ 비용 0.** 정지한 Pod도 디스크 요금이 나간다는 것을 상태·정산 화면에 항상 표시한다.

## 3. 사용자 화면 (명령)

| 명령 | 동작 |
|---|---|
| `/gpu-start` | GPU 종류·개수, 최대 사용 시간(기본 2시간·상한 8시간, 설정 가능), 이번 세션 예산을 받는다 → **예상 비용(시간당 단가 × 최대 시간)** 을 보여주고 확인 → 생성 + Pod 안에 TTL 자동 정지 설치(+ 선택: 공식 Idle Monitor 부착) → 장부 기록 |
| `/gpu-status` | 이 세션·전체의 켜진/정지된 Pod, 경과 시간, 남은 TTL, 누적 요금(추정), 정지 Pod 디스크 요금. 조회만 |
| `/gpu-stop` | Pod 선택 → 결과 파일 회수 여부 확인 → **정지 / 삭제** 선택 → 실행 → 최종 요금(추정 + RunPod 청구 대조) 표시 → 장부 마감 |
| (선택) `/gpu-extend` | TTL 연장. 새 예상 비용을 보여주고 확인 |

- 세션 종료 시: **행동하지 않고 경고만.** 켜진 Pod가 남아 있으면 "4090 1대 켜짐, N분 뒤 자동 정지, 현재 $X"를 알린다(표시 경로는 §6 검증 항목).
- 선택: 상태줄에 켜진 Pod 수·누적 요금.

## 4. 구성 요소

```
moni_pod/
├─ .claude-plugin/plugin.json      # 플러그인 매니페스트 (스펙은 최신 문서로 확인)
├─ commands/                       # gpu-start.md · gpu-status.md · gpu-stop.md (· gpu-extend.md)
├─ hooks/hooks.json                # 잠금 훅(PreToolUse) + 세션 종료 경고(SessionEnd)
├─ src/moni_pod/
│  ├─ ledger.py                    # 장부: ~/.moni_pod/ledger.json (Pod별 세션·생성시각·GPU·단가·TTL·예산·상태·회수여부)
│  ├─ runpod_api.py                # RunPod REST 래퍼(생성·정지·삭제·조회·가격·청구). 키는 환경변수
│  ├─ cost.py                      # 추정(단가×가동시간, 정지 Pod 디스크) + 청구 대조
│  ├─ guard.py                     # 잠금 판정: 명령 경유 여부 확인(1회용 승인 토큰)
│  ├─ ttl.py                       # Pod 안 자동 정지 명령 생성
│  └─ cli.py                       # 명령들이 부르는 진입점
├─ tests/                          # 목 기반. 실제 생성 테스트는 사용자 승인 후 1회
└─ docs/ (PLAN.md, adr/)
```

### 잠금 훅의 핵심 난점 (설계 필요)
- 정문(`/gpu-start`)을 거친 생성만 통과시켜야 한다. 안: 명령이 사용자 확인 직후 **1회용 승인 토큰**(대상·사양·만료 수십 초)을 장부에 쓰고, 훅은 토큰과 사양이 일치하는 호출만 1회 허용, 나머지는 거부.
- 막아야 할 경로: 공식 MCP의 생성·재시작·삭제 도구, `Bash`로 실행한 `runpodctl create/start/remove`, `curl`로 REST 직접 호출. 도구 이름·인자 형식은 실제 플러그인을 설치해 확인.
- 우회 가능성(예: 셸 스크립트 안에 숨긴 호출)은 완벽히 막을 수 없다 → README에 "가드의 한계"로 정직하게 적고, 최후 방어선(TTL)과 RunPod 계정 쪽 한도(선불 크레딧·auto-pay 끄기)를 함께 권장.

## 6. 착수 전 확인할 것 (M0)

1. Claude Code 플러그인 구조·매니페스트 최신 스펙. 플러그인에 명령·훅을 함께 담는 방법
2. **PreToolUse 훅이 MCP 도구 호출을 매처로 가로챌 수 있는지**(도구 이름 패턴), 거부 시 사유 전달 방식
3. **SessionEnd 훅 출력이 사용자 화면에 보이는지.** 안 보이면 대안(데스크톱 알림·로그·상태줄)
4. 상태줄 커스터마이즈로 외부 값(누적 요금) 표시 가능 여부
5. RunPod REST API: Pod 생성 시 시작 명령(TTL 자동 정지) 주입, 정지·삭제, 시간당 단가 조회, **청구(billing) 조회와 반영 지연**
6. Pod 안 자동 정지 방식: Pod 내부에서 자기 자신을 정지시키는 공식 방법(환경변수 `RUNPOD_POD_ID` + API 키 주입 여부 등)
7. 공식 Idle Monitor를 Pod 안 스크립트판으로 자동 부착할 수 있는지(라이선스 포함)
8. 선행조사 재확인: "시간 누적 자원 + 에이전트" 가드가 그새 나왔는지

### M0 결과 — 2026-10-06 지휘부 승인
보고: `docs/reports/2026-10-06-m0.md`. ADR: `docs/adr/0001`(구조)·`0002`(잠금)·`0003`(TTL).

승인된 변경:
1. RunPod REST **v2**(`https://api.runpod.io/v2`) 사용. v1은 2026-11-15 폐지.
2. 토큰은 **사용자가 직접 입력한 명령**(`UserPromptExpansion`)에서만 발급 + 실행 직전 PreToolUse **`ask`**(네이티브 권한 프롬프트)로 두 번째 확인.
3. 명령은 공식 MCP가 아니라 **자체 CLI**(REST v2)를 거친다. 직접 `stop`은 허용(지출을 줄이기만 함).
4. 공식 Idle Monitor는 라이선스가 없어 부착하지 않음 → README 링크만.
5. 상태줄은 opt-in(플러그인이 메인 statusLine을 설정할 수 없음 → 사용자 settings.json).
6. TTL = 시작 1회당 최대 연속 가동 시간. `/gpu-extend` 방식은 M2에서 결정.
7. 세션 종료 경고 = Windows 토스트 + 다음 세션 시작 시 리마인더(SessionEnd 화면 출력은 신뢰 불가).

승인 조건(해당 마일스톤에서 검증·보고):
- A. [M4 전] `ask`가 bypassPermissions·auto 모드에서도 실제로 프롬프트를 띄우는지 실험. 자동 승인되면 대안(`/moni-pod:gpu-confirm` 직접 입력 2단계).
- B. [M3/M4] MCP·runpodctl로 한 직접 stop은 허용하되 PostToolUse 또는 `/gpu-status` 시 REST 대조로 장부 동기화.
- C. [M2] TTL 엔트리포인트는 원래 템플릿의 엔트리포인트를 조회해 감싸는 방식으로 일반화. PyTorch 공식 템플릿 + (가능하면) CPU 템플릿에서 확인. Pod 범위 키 자기 정지도 실과금 1회에서 확인.
- D. 누적 지출 보고에 Anthropic 쪽 headless 실험 비용도 포함.

## 7. 결정 사항 / 미정

**확정 (사용자 승인 2026-10-06, 지휘부 전달) — M2부터 적용:**
- TTL 기본 **2시간**, 상한 **8시간**. 상한 초과 요청은 `/gpu-start`에서 거부. 사용자가 설정 파일로 변경 가능.
- 세션 예산 기본 **$2**. 예상비용(단가 × TTL)이 예산을 넘으면 시작 거부 + 이유 표시. 설정으로 변경 가능.
- 공식 Idle Monitor: 부착하지 않음(라이선스 없음, M0 결론) → README 링크만.
- 위 값은 작업 0001의 실과금 테스트 상한($3)과 별개.

**미정:**
- 지원 범위: 처음엔 RunPod Pod만(서버리스 제외) — 다른 클라우드 확장은 공개 후 검토
- 저장소 이름: `moni_pod`(폴더명) 그대로 공개할지
