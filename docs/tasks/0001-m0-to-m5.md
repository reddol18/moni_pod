# 작업 0001 — M0 검증부터 M5까지

- 지시: 지휘부 · 2026-10-06 (사용자 결정)
- 범위: `docs/PLAN.md`의 M0~M5. **M6(공개)는 이번 범위 아님.**
- 이후 순서(참고): M5까지 끝나면 사용자가 실제 GPU 작업에 moni_pod를 써서 실용성을 확인한다. 그 결과로 M6 여부를 정한다.

## 사용자 위임 사항 (이번 작업 한정)
- **설치는 알아서 진행해도 된다**(사용자 승인 완료): RunPod 공식 Claude Code 플러그인(`runpod/runpod-plugins-official`), `runpodctl`, `uv`·Python 의존성, 기타 개발에 필요한 CLI. 설치 후 무엇을 어디에 설치했는지 보고한다.
- git 로컬 초기화(`git init`)와 로컬 커밋은 마일스톤 단위로 해도 된다. **GitHub 원격 생성·푸시는 하지 않는다.**

## 위임되지 않은 것 (매번 사용자 승인)
- **실제 과금 호출**(Pod 생성·재시작). 승인 요청 시 GPU 종류·개수, 최대 시간, 예상 비용을 함께 보여준다.
- **이번 작업 전체 실과금 상한: $3.** 나머지 크레딧은 이후 실사용 확인용이다. 누적 지출을 마일스톤 보고마다 적는다.
- 실과금 테스트는 가장 싼 GPU(또는 CPU Pod로 대체 가능하면 CPU), TTL 10분 이내를 기본으로 한다.
- Pod 삭제(terminate)는 테스트로 만든 Pod에 한해, 사용자에게 알린 뒤.

## 단계별 지시
1. **M0 검증** — PLAN §6의 8개 항목을 최신 공식 문서·실험으로 확정하고 `docs/adr/0001`(플러그인 구조), `0002`(잠금 방식: 1회용 승인 토큰 또는 대안)를 쓴다. 공식 플러그인을 설치해 MCP 도구 이름·인자 형식을 실제로 확인한다. **M0 결과를 지휘부에 보고하고 확인받은 뒤 M1로 넘어간다**(설계가 바뀔 수 있는 단계).
2. **M1~M5** — PLAN §5의 완료 기준대로. 마일스톤마다 보고(만든 것 / pytest 숫자 / 설계와 달라진 점 / 막힌 점 / 누적 지출).
3. 설계 원칙(PLAN §2) 5개는 바꾸지 않는다. 바꿔야 할 이유가 생기면 구현 전에 지휘부에 알린다.
